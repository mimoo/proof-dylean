Traces and Traceful

Everything in DyLean happens on a trace: an append-only log of what the protocol and the attacker did. Programs run on the execution trace, the log as it really is. Proofs reason about the proof trace, the same log with ghost annotations on some entries, which erases back to the execution trace. Protocol steps are written in Traceful, a small state-and-failure monad over the execution trace whose type guarantees the log only grows. This page goes through each layer, from Trace up to reachability.

1 · A trace is a snoc-list

inductive Trace (α: Type) where
  | nil: Trace α
  | snoc: Trace α -> α -> Trace α

A trace grows at the right: .snoc tr e is tr with e appended. It is generic in the entry type α; the execution trace and the proof trace are both instances.

The prefix order

inductive Trace.le : Trace α -> Trace α -> Prop where
  | equal:  (tr: Trace α) -> Trace.le tr tr
  | extend: (tr1 tr2: Trace α) -> (e: α) -> Trace.le tr1 tr2 -> Trace.le tr1 (.snoc tr2 e)

tr1 ≤ tr2 means tr1 is a prefix of tr2. It is reflexive and transitive, and almost every theorem in DyLean is stated "for every later trace" using it: labels' corruption is monotone, invariants carry _later lemmas, canFlow quantifies over extensions. le_imp_prefix_eq recovers a prefix from a longer trace: tr1 ≤ tr2 → tr2.prefix tr1.length = tr1.

Indices are timestamps

def Trace.at (tr: Trace α) (i: Nat) (h_i: i < tr.length) : α := …
theorem Trace.at_le : tr1 ≤ tr2 → tr1.at i h_i = tr2.at i _      -- entries never move

Entry i is the one appended when the trace had length i, so an index is a timestamp. Because extension never changes existing entries, an index is a stable name for an entry: random bytes are named by the index they were generated at, stored states by their handle, events by the time they were logged.

2 · Typed entries in one trace

A trace holds messages, random-byte records, events, stored states and more, each with its own type, but a Trace has a single entry type. One class connects them:

class TraceEntryHas (EntryT: Type) (α: Type) where
  inj: EntryT → α
  proj: α → Option EntryT
  inj_proj_eq: ∀ x y, (proj x = some y) = (x = inj y)

def Trace.append [TraceEntryHas EntryT α] (tr: Trace α) (entry: EntryT) := .snoc tr (TraceEntryHas.inj entry)
def Trace.at? [TraceEntryHas EntryT α] (tr: Trace α) (i: Nat) : Option EntryT :=
  if h_i: i < tr.length then TraceEntryHas.proj (tr.at i h_i) else none

Appending injects a local entry into the global type. Looking up at a local type projects, and returns none if the index is out of range or holds an entry of another type. That second case is why reading a stored state at a wrong handle fails instead of returning garbage.

3 · The execution trace

class ExecTraceTypes where
  ExecT: Type
def ExecTrace.Entry [ExecTraceTypes] := ExecTraceTypes.ExecT
abbrev ExecTrace [ExecTraceTypes] := Trace ExecTrace.Entry

class ExecTraceTypes.Has (ExecEntryT: Type) extends TraceEntryHas ExecEntryT ExecTrace.Entry

The global entry type is a parameter: a protocol builds it with #combine as a tagged sum of the entry types it uses, and declares it as the execution entry type. Each action declares its own small entry type, for example Network.ExecEntryT := {msg} and Random.ExecEntryT := {length}, and asks for ExecTraceTypes.Has of it. That instance is found by chaining single inclusion steps up to the global sum, as the #combine page explains.

4 · The proof trace wraps it

Some facts proofs need are not in the execution at all. When genRand runs, the program only records a length, but the proof needs to know which label those bytes have. So each entry kind also has a proof entry type with any ghost fields, and an erasure back to the execution entry:

class ErasableProofEntry (ExecEntryT: outParam Type) (ProofEntryT: Type) where
  erase: ProofEntryT → ExecEntryT

structure Random.ExecEntryT  where length: Nat
structure Random.ProofEntryT where length: Nat; label: Label; usage: Usage
instance : ErasableProofEntry Random.ExecEntryT Random.ProofEntryT where
  erase | {length, label := _, usage := _} => { length }

abbrev Network.ProofEntryT := Network.ExecEntryT     -- no ghost data
instance : ErasableProofEntry … := ErasableProofEntry.default Network.ExecEntryT   -- erase is the identity

The proof trace is then a separate Trace over the combined proof entry type, and it erases entry by entry:

class ProofTraceTypes [ExecTraceTypes] where
  ProofT: Type
  [tc: ErasableProofEntry ExecTraceTypes.ExecT ProofT]
abbrev ProofTrace := Trace ProofTrace.Entry

def Trace.erase (tr: ProofTrace) : ExecTrace :=
  match tr with
  | .nil => .nil
  | .snoc trBefore entry => .snoc trBefore.erase entry.erase

So a proof trace has the same length as its erasure, entry i erases to execution entry i, and prefixes commute with erasure. "Wraps" means exactly that: a proof trace is an annotation of an execution trace, index for index. Only a few entry kinds carry ghost data; in SignedDH it is the random-bytes records.

5 · The trace invariant

class SubTraceInvariant (ProofEntryT: Type) [ErasableProofEntry ExecEntryT ProofEntryT] where
  invariant: ProofTrace → ProofEntryT → Prop

def Trace.Invariant (tr: ProofTrace) : Prop :=
  match tr with
  | .nil => True
  | .snoc trBefore entry => trBefore.Invariant ∧ entry.Invariant trBefore

Each entry kind says what must hold of the proof trace before it for it to be appended: messages must be publishable, events must satisfy their event invariant, random entries have no condition. The trace invariant is the conjunction over all entries, each judged against its own prefix. It is defined on the proof trace, because the conditions talk about ghost data such as labels. Two lemmas do most of the work:

theorem Trace.invariant_append : (tr.append entry).Invariant = (tr.Invariant ∧ SubTraceInvariant.invariant tr entry)
theorem Trace.invariant_at : tr.Invariant → (tr.at i h_i).Invariant (tr.prefix i)

The first is how writing is checked; the second is how reading recovers what was checked. The Hoare triple page builds on both.

6 · Traceful: the monad

def Traceful (a: Type) := (trIn: ExecTrace) → Option a × { trOut: ExecTrace // trIn ≤ trOut }

A Traceful a takes the current execution trace and returns an optional result and a new trace, together with a proof that the new trace extends the old one. It is a state monad over the trace, with failure, and the subtype makes "the trace only grows" a property of every program rather than something to prove later.

instance : Monad Traceful where
  pure x := fun tr => (some x, ⟨ tr, by grind ⟩)
  bind x f := fun tr =>
    let (xOptVal, trMid) := x tr
    match xOptVal with
    | none => (none, trMid)                              -- failure stops, keeping what was appended
    | some xVal =>
      let (optRes, trOut) := f xVal trMid.val
      (optRes, ⟨ trOut.val, by grind [Trace.le_trans] ⟩)

instance : Alternative Traceful where
  failure := fun tr => (none, ⟨ tr, by grind ⟩)          -- so guard works
Failure does not roll back. If a step appends two entries and then fails, the trace keeps those two entries. That is why the Hoare triples demand the invariant even on failure: whatever was appended before the failure must have been allowed.
Programs never see the proof trace. Traceful is over ExecTrace. The proof trace exists only in specifications: wp runs the program on tr.erase and asks for a proof trace that erases to the result.

The three primitives

def appendEntry [ExecTraceTypes.Has EntryT] (entry: EntryT) : Traceful Nat :=
  Traceful.mk (fun tr => (some tr.length, ⟨ tr.append entry, by simp [Trace.append_le] ⟩ ))   -- returns the new index
def getEntry [ExecTraceTypes.Has EntryT] (timestamp: Nat) : Traceful EntryT :=
  Traceful.mk (fun tr => (tr.at? timestamp, ⟨ tr, by grind ⟩ ))                               -- typed lookup, may fail
def getTimestamp : Traceful Nat :=
  Traceful.mk (fun tr => (some tr.length, ⟨ tr, by grind ⟩))

Every action in the library is built from these. genRand appends a length record and returns the term "random bytes at that index". sendMessage, logEvent and storeGlobalState append their entries and return the index, which is the handle. receiveMessage and getGlobalState are getEntry at their type.

A step, desugared

def Client.initiate (me) : Traceful (Nat × Nat) := do
  let xSk ← Random.genRand 32
  let xPk := DiffieHellman.dhPk xSk
  ProtocolEvent.logEvent (ClientInitiateEvent me xPk)
  let stHandle ← storeLocalState me { xPk, xSk }
  let msgHandle ← sendMessage (serialize { xPk })
  return (stHandle, msgHandle)
genRand 32 >>= fun xSk =>
  let xPk := dhPk xSk
  logEvent … >>= fun () =>
  storeLocalState … >>= fun stHandle =>
  sendMessage … >>= fun msgHandle =>
  pure (stHandle, msgHandle)

Run on a trace of length n, it appends four entries: a random record at n, so xSk is the term "random bytes at n"; the event at n+1; the state at n+2; the message at n+3. It returns some (n+2, n+3). In the honest run, n = 4, which is why Alice's state has handle 6.

Pure failures: Err

def Err := OptionT Id   deriving Monad, Alternative
instance : MonadLift Err Traceful := { monadLift x := Traceful.mk fun tr => (x, ⟨ tr, by grind ⟩ ) }

Parsing can fail but does not touch the trace, so Comparse.parse returns Err a, and Lean inserts the lift automatically in let msg ← parse msgBytes. The lifted computation leaves the trace unchanged and fails the step if parsing fails.

7 · Reachability: which traces can happen

structure ReachabilityConfig where
  Input: Type
  PreCond: Input → ExecTrace → Prop
  step: Input → (Output: Type) × Traceful Output

inductive Trace.Reachable (config: ReachabilityConfig) : ExecTrace → Prop where
  | Base: Trace.Reachable config Trace.nil
  | Step: (input: config.Input) → config.PreCond input tr → Trace.Reachable config tr →
          Trace.Reachable config (((config.step input).snd).run tr).snd

A reachable trace is anything built from the empty trace by running allowed steps, with arguments chosen freely, which is how the attacker controls scheduling. Reachability is about execution traces only; Reachable_implies_Invariant is the theorem that puts an invariant proof trace behind each one.

For a concrete program such as the sanity-check runs, PreservesReachability is the execution-side counterpart of a Hoare triple. Its lemmas for bind, pure and registered steps let honestAttacker_PreservesReachability show that the honest run's trace is reachable, step by step.

8 · Writing against abstract trace types

SignedDH's specification and proofs never mention the concrete combined entry types. They are written against bundle classes that only promise "some global trace type containing these entry kinds":

classbundles
HasExecTraceExecTraceTypes, a Has for each of the seven entry kinds, and base attacker knowledge
HasProofTraceProofTraceTypes and a Has for each proof entry kind
HasTraceInvariantTraceInvariant, a Has per kind, and the attacker-knowledge theorems

Instance.lean builds the concrete types with #combine +toplevel and then discharges each class with an empty instance. The proofs therefore depend only on injection and projection, never on the shape of the sum.
